# BambuPalette · 混色耗材色彩管理器

<img src="assets/logo.png" alt="BambuPalette" width="260">

一款独立的 Windows 桌面程序，用来管理自己的打印耗材颜色，并算出**任意两种耗材按 10%–90% 的 81 种比例混出来的颜色**——让你在 Bambu Studio 的「添加混色耗材」里一次就配对成功。

程序不联网、不依赖网页，所有数据都存在本机。

窗口**打开就是最大化**：这张颜色表越宽越好，默认开成一个小窗口只会让人每次启动都先手动放大一次。（所以程序不记忆窗口大小，永远满屏打开。）

想知道自己装的是哪一版：右键 `BambuPalette.exe` →「属性」→「详细信息」，里面的**文件版本 / 产品版本**就是版本号（构建时从 `app/__init__.py` 读出来写进 exe，不会跟程序里显示的版本对不上）；程序标题右上角「帮助」按钮弹出的那个窗口里，最后一段也写着同一个号。

> **给脚本和二次开发的提示**：设置环境变量 `BAMBU_PALETTE_DATA_DIR` 可以把数据目录指向别处。
> 任何以程序方式打开主窗口的脚本都**应该**设它，否则脚本构造窗口时会把演示数据写进用户真正的耗材库。
> 每次保存还会在旁边留一份 `filament-library.json.bak`（上一版），用来兜住这类意外。

---

## 一、它能做什么

### 颜色配方（第一页）

1. **录入耗材**：点「添加耗材」，填名称、品牌、耗材种类、颜色（RGB）、备注。
2. **自动算出全部混色**：录入 N 种耗材，程序立刻列出所有两两组合 `C(N,2) × 81` 个混色。
   - 3 种耗材 → 3 对 × 81 = **243** 个混色
   - 4 种耗材 → 6 对 × 81 = **486** 个混色
   - 5 种耗材 → 10 对 × 81 = **810** 个混色
   - 每对的 81 个比例就是 Bambu Studio 允许的 10%、11% … 90%。
3. **点开任何一个混色**，右侧立刻告诉你：
   - 它由**哪两种耗材**混成（耗材丝1 / 耗材丝2，带颜色和名称）；
   - **比例是多少**（例如 `27% + 73%`）；
   - 预测出来的颜色值（hex / RGB）；
   - 下面还有一行「**在 Bambu Studio 里这样复现**」，把该选哪两种耗材、比例拖到多少、效果预览应该显示什么颜色都写清楚了，照做即可。
   - 「复制配方」按钮把这一段配方文字复制到剪贴板。
4. **双向定位**：
   - 中间色块按 RGB 排列；点任意一个色块，右侧显示配方。被选中的那个色块会用**它自己的颜色**（降低透明度）框起来，其余色块保持原样、不会被压暗——这样你能一眼看出它和周围混色的关系。
   - 点一下色块之间的**空白处**（或按 Esc）就取消选择。
   - 双击一个**两色**混色 → 只看这一对耗材的全部混色。这时网格上方会弹出一条**筛选提示**，写明「只看 某某 × 某某 的 81 个配比：现在显示 81 个，另外 66339 个没有显示」，旁边就是一个「显示全部颜色」按钮；工具栏和右侧面板上的按钮同时也会变成强调色 / 改成「取消筛选，回到全部颜色」，点哪个都能回到全部颜色。
   - 双击一个**三色**混色 → 不会缩成两色。三色配方的父母是**三卷**料，按其中两卷去筛只会显示出另一种颜色的 81 个配比，所以程序只在右侧继续显示它本身。
   - 想反查？在「目标颜色」里选一个你想要的色，点「**找最接近的颜色**」，程序用 CIEDE2000 色差在当前显示的全部颜色里找最接近的那一个。**耗材本色也在候选里**——问一个你已经拥有的颜色，答案就是它本身（ΔE00 = 0.00），不会再绕到旁边一个混色上；状态栏会写明「就是耗材本色」。
    - 这个按钮**一直都能按**：**没填目标颜色也会真的去找**——先拿你在颜色表里选中的那个颜色来比，表里也没选就拿 R / G / B 三个数字框里的值；用哪个都会写在状态栏里（「目标颜色取自你正看着的 #RRGGBB」/「目标颜色取自数字框里的 RGB 0, 0, 0」），并且顺手填进「目标颜色」，不会悄悄拿一个你没看见的颜色去搜。耗材库为空时按它，会告诉你要先添加耗材。**打开软件时「目标颜色」预置的就是 000**（1.6.17 起）：以前它是空的，而空着的数字框读出来还是 `(0, 0, 0)`——点下去照样拿纯黑去查，屏幕上却看不出目标是什么；现在黑色就明明白白写在框里，要换随时改。
5. **排序与搜索**：可按 RGB、按明度、按色相、按耗材对、按名称排列；搜索框里输入 `3D7B` 这样的 RGB 片段，或耗材名称 / 品牌 / 种类，都能筛。「找最接近的颜色」也只看当前筛出来的这些。
6. **耗材本色和混色在同一张表里**：耗材丝**本身的颜色**也作为一个可选项列在网格中，和它的混色一起按「排序」下拉框排队（点开时写着「耗材本色」，不是混色）。
   - 2 种耗材 → 81 个混色 + 2 个本色 = **83 个颜色**
   - 3 种耗材 → 243 + 3 = **246 个颜色**
   - 本色项**跟着「排序」下拉框排在同一条队列里**，不会被顶到最前面。按 RGB 时它就是按 RGB 插在中间（例如 `#17181C` 排在最暗的位置），按明度 / 色相 / 名称也一样；只有「按母材组合」会让它们聚在最前面，因为它们本来就不属于任何一对母材。
   - 表格**下面是状态栏那一行**，写着当前规则的完整说明（两色 81 个配比、三色每三卷 2556 个配比、共多少个配比 / 本色 / 去重后多少个颜色、按什么排列、筛选时另外有多少个没显示）。窗口窄的时候它会自己折行，**不会把窗口撑宽**——左边「我的耗材」和右边「颜色配方」之间的分隔条可以随便拖。（这句话讲的是这张颜色表，所以在「图像转换」页不显示，免得占着一行说无关的事；切回「颜色配方」立刻恢复。）
7. **删除耗材**：选中后按 **Del**（或 Backspace）直接删除，点「删除」按钮也是**立刻删掉、不再弹确认框**。删错了重新加一个即可。
8. **颜色是「填」进去的，不是「挑」出来的**：程序里没有弹出式取色器（那个带色轮和吸管、按钮还是英文的窗口已经删掉了）。所有颜色都用同一个输入框填写——上面一行是 `#RRGGBB`，下面一行是 R / G / B 三个数字框，填哪个都行，两边会互相同步。

   **添加 / 编辑耗材的对话框就是填颜色的地方：**

   ![添加耗材](samples/add-filament.png)

   - **新耗材没有预设颜色**：空白表单里 `#RRGGBB` 是空的、R / G / B 三个框也是空的（不是 0, 0, 0），颜色块写着「未选择」，下面那行提示直接告诉你该怎么填。**没填颜色之前，「确认」和「下一个」都是灰的**——程序不会替你猜一个黑色，也不会因为你手滑点了一下就存下一条你没选过颜色的耗材。
   - 「确认」左边有一个「**下一个**」：按下去会先把这一卷存好，然后**立刻弹出一个空白表单接着录下一卷**，不用存一次、关一次窗口、再点一次「添加耗材」。录 41 卷就是一串「下一个、下一个、下一个」，最后一卷点「确认」收工。「取消」和「确认」都还是各管各的。
   - 顶部的「目标颜色」用的也是同一个输入框。
9. **列表怎么显示颜色**：左边每一行是「名称 + 颜色」。没填名称 / 品牌 / 种类的耗材没有别的名字可用，程序原来会把颜色值再印一遍（`#000000   #000000`），现在第二列换成 RGB 数字（`#000000   RGB 0, 0, 0`）。
10. **只有一种耗材时**：还不会产生混色，但这一种耗材自己的颜色会照常显示在中间的网格里。
11. **没有「载入示例耗材」**：以前空库时会提供一个塞进 4 条示例数据（示例白 / 示例黑 / 示例红 / 示例蓝）的按钮，现在删掉了——这个程序不替你决定库里有什么颜色。
12. **界面上的文字都能用鼠标选中复制**：提示、配方、状态栏、右侧「在 Bambu Studio 里这样复现」那一段，全都可以拖选后 Ctrl+C。配方行是选中颜色时才现做出来的，程序在应用层挂了过滤器，新出现的标签一样能选中。
13. **用完的料可以先藏起来**：在「我的耗材」里右键任意一卷 →「**隐藏（不参与混色）**」。这一行**还留在表里**（只是变灰、后面标着「（已隐藏）」），但它的颜色会从所有配方里撤出去——它不再是任何两色 / 三色配方的原料，自己那一色也不进「全部颜色」，图片转模型的候选里也没有它。买回来之后右键「**取消隐藏（重新参与混色）**」即可，别的什么都没被改动。
    - 为什么不在匹配器、网格、「全部颜色」、导出里各过滤一遍：那四处迟早会走岔。程序让所有配方表都从 `library.visible` 建起来，藏一卷料就等于换了一个耗材库。
    - 藏一卷料后第一次打开要等的那几分钟，是在重算三色混色——那三色配方表是跟着耗材清单走的，清单变了它就得重来。
    - 隐藏状态**只在需要它的那一条档案上写一个字节**：没隐藏过任何耗材的档案，格式与以前完全一样。

### 图片转模型（第二页）

![图片转模型页](samples/picture-page.png)

把一张图片变成可以打印的**平面多色底板**：

1. 「导入图片」选择图片。
2. 程序在你的**耗材库 + 全部混色库**里为图片的每一种颜色找最接近的颜色。
3. 左侧是**原图**（就是你导入的那张图片本身，一直保持原样），右侧「打印图片需要的颜色」清单：
   - **点右侧某个颜色** → **右侧「预览」**里该颜色的区域高亮，其余变淡；**左边「原图」不动**——它永远是你导入的那张图，用来对照。
   - **高亮会一直留着**（1.6.12 修的）：放大、缩小、点到别的软件再回来，预览里的色块都在。以前只在「刚点完」的那一帧看得见，画面一重绘就没了。
   - **点图片上某块区域** → 右侧清单自动跳到对应的颜色。**清单顺序不会因为这个点击而变**：以前一点就把那一行挪到最上面，于是鼠标底下停的那一行变成了另一种颜色，看着像点错了；现在排序就是排序，程序只把当前行高亮出来、滚到看得见的位置。**点预览里的色块和点清单里的那一行是同一件事**（1.6.12 起两边完全一致）。**在「按色块边缘选择」下，点图片选中的是「这一块」本身**（1.6.17 起）：清单会变成**一行一块**，下面那排编辑按钮改的也是块（见第 5 条）。
   - **再点一次同一个颜色 = 取消选中**（1.6.12 新增）：点清单里已经选中的那一行、或点预览里正在显示的那一块，就取消选中，预览**退回上一个看过的颜色**；没有上一个了，就退回整张预览。所以「看对比」不用再点一遍别的颜色再点回来。**在「按色块边缘选择」下也成立**（1.6.20 起）：以前块模式里「取消选中」会翻出上一个看过的**块编号**，可那个编号在新的一组块里照样合法，看起来就像「跳到了另一块」；现在块模式取消选中就是什么都不选，预览连高亮一起收掉（按颜色选择仍然退回上一个看过的颜色——那里「翻回上一个」是有用的）。**清单里一个都没选中时，预览什么都不画**（1.6.21 起，用户在图三之后报的 bug）：点清单下面的空白处、「多选」里点掉最后一行、程序自己清空选择——只要选中集是空的，预览里那一块的压暗和描边就一起收掉，不会还留着上一块亮着而按钮已经灰了。这条规矩现在挂在「有没有选中」本身，而不是挂在某一条操作路径上。
   - **刚匹配完不选中任何颜色**（1.6.14 起）：以前这里会自动高亮第一行，看着像程序替你挑了一种颜色，也让「取消选中」无从下手；现在高亮只来自你自己点的东西（删除、合并、更换颜色、撤销这些编辑仍然跟着你点过的那一块走，不会跳回第一行）。**换方案、重新匹配也一样**（1.6.15 起）：换了另一套料就别再标着上一套里点过的颜色——没点颜色时预览既不压暗也不描边。
   - **要看某一种颜色的详情，在清单里双击它**（1.6.13 起）：弹出「颜色详情」窗口，把这种颜色讲透（图片里的颜色、匹配到的颜色、色差、配方）。这块内容以前占着右栏的一个常驻面板（「选中的颜色」），现在按需弹出来，右栏于是空出来给了「耗材方案」。窗口**不是模态的**：开着它照样能点别的色块，里面的内容跟着换；关掉它也不影响你选中的是哪个色块。
4. **颜色详情窗口**（上面那条说的那个）里有什么：
   - 「**图片里的颜色**」是图上这块区域**自己的平均 RGB**，「**匹配到的颜色**」是耗材/混色库里真正能打出来的颜色——两个色块并排显示，下面各自的 hex、RGB、像素数和占比一目了然；
   - 显示两者的 **CIEDE2000 色差 ΔE00**，并给出「很接近 / 接近 / 偏差较大」的判断；
   - 「匹配到的颜色」下面写着它的**配方**（哪两种耗材、各多少百分比），单色耗材则标明「耗材本色」；
   - 觉得不合适？点「**更换颜色**」从「全部颜色」里手动挑一个（下面第 5 条）；
5. 清单下面一排**编辑按钮**，改的是「这一块到底打不打、打成什么颜色」——按颜色选就是这一个颜色的取舍，**删除或合并都会连原图一起改**（在「按色块边缘选择」下 1.6.19 起、按颜色选择下 1.6.20 起，见第 9 条）。从左到右就是**多选、删除、合并、更换颜色、撤销、恢复**：
   - 「**多选**」——一个开关。打开以后**单击就是把这一种颜色加进选择、再单击取消这一种**，不用按住 Ctrl，按钮会变蓝提醒你正开着；关掉就回到「一次只选一种」。打开时**点左边「预览」里的色块也一样算数**——预览和右边清单本来就是同一批色块，指哪一块就是选中哪一块；关掉时点预览只是「看看这一块是哪个颜色」。**取消掉的那一块，预览里也不再高亮它**（1.6.16 起：列表说没选中的颜色，预览不画它的压暗和描边）。选中两种以上才会亮起的「合并」就需要它（当然按住 Ctrl 点也一样）；
   - **「按色块边缘选择」下，这一排按钮改的是「块」**（1.6.17 起）：清单变成**一行一块**（按大小排，一行写着「第 N 块」、它印出来的颜色、这块的配方和占比），多选选的是块，删除删掉的是**选中的那几块**（留空、不打印，和按颜色删除一模一样），合并是**在你选的这些块里挑一种颜色、把选中的块全变成它**，更换颜色是**选中的块一起换成新颜色**；点图片选中的也是块——「这一块」和「这一种颜色」从此是两件事，这正是这个模式存在的理由（眉毛、描边只有一两个像素宽，按颜色选要点得极准）。四种操作**都在撤销范围里**，切模式也一样（见下面「撤销 / 恢复」）。**做完一次编辑，只会选中刚改动的那一块**（1.6.20 起）：以前换一块颜色时，紧挨着的另一块只要有一半压在改动区域上就一起被选中，列表里于是高亮两行，看着像你动了两个地方；现在是一块一块地认（各自取「落在哪个块上最多」），换一块就只选中那一块。**这一栏的标题也跟着模式走**（1.6.20 起）：按色块边缘选择时它叫「**图片上色块的颜色**」，因为它装的是块，不再是「打印图片需要的颜色」那样一种颜色一行。

     ![按色块边缘选择：清单一行一块](samples/picture-blocks.png)
   - 「**删除**」——选中一种或几种颜色，删掉的地方**留空、变成透明**：那块既**不打印**，底下也**没有底板**，模型上就是一个洞。想要衣服挖空、眼睛留白这类效果就用它。**也可以直接按键盘上的 Del**（1.6.19 起），和点这个按钮一模一样；**删的是块，原图里那些像素也一起变透明**（1.6.19 起），**按颜色删也一样改原图**（1.6.20 起，用户在图三里报的就是「原图没跟着预览一起改」）——删掉一种颜色 = 这些像素在源图里变透明，之后「重新匹配」和「按当前色块重新匹配」都从改过的原图出发，删掉的地方不会再被匹配回来。按钮上只写「**删除**」两个字（1.6.20 起；Del 好使这件事写在右上角「帮助」里）。只有「更换颜色」不动原图，它说的是「这块地方这一次用哪一卷来印」；
   - 「**合并**」——选中**两种以上**颜色，点合并会弹出窗口，从这几种里挑一种作为合并后的整体颜色，选中的区域就都用它打印。**合并的是块，原图上那几块也并成留下的那一块**（1.6.19 起），**按颜色合并同样改原图**（1.6.20 起）：合并两种颜色 = 这些像素在源图里并进留下的那一块——重新匹配之后它们还是同一种颜色，不会又分开。**写进原图的是「留下来的那一块本来就在的颜色」，不是这卷耗材印出来的颜色**（1.6.21 起，用户在图三之后的第 2 条）：原图色块 a 对应预览色块 b、原图色块 c 对应预览色块 d，b 和 d 合并之后，原图里 c 也并进 a、用的是 a 自己的颜色——所以原图的颜色集合一点都不变，变的只是色块大小，再看「按当前色块重新匹配」就是拿原图自己剩下的那几种颜色去挑卷；
   - 「**更换颜色**」——给当前选中的这一种颜色换一个：从「全部颜色」里挑（下面第 7 条）。它和旁边的按钮长得一样，**不带蓝底**——这一排都是对选中结果做的动作，整页只有右下角那个「生成 3MF」是蓝色的，因为那才是「干完了」；
   - 「**撤销 / 恢复**」——上一步删了、合并了或者换了颜色，按 **Ctrl+Z** 退回去，按 **Ctrl+Y** 再做回来（也可以直接点按钮）。最多记 64 步；**「按当前色块重新匹配」和换一套方案也各算一步**（1.6.16 起）：整张匹配、右边的方案表、勾选的那一套会一起退回去 / 做回来，不用怕点一下就把改到一半的东西弄丢；**「点图片时」换一种选择方式同样算一步**（1.6.17 起）：从「按颜色选择」切到「按色块边缘选择」也能 Ctrl+Z 退回去，切回去以后清单又变回一行一种颜色——列表、预览、按钮的可用状态都跟着那一步一起回去；**删除或合并改过原图，Ctrl+Z 会把原图一起退回去**（1.6.19 起；1.6.20 起按颜色的删除 / 合并同理）——图、标记、色块、按钮全部回到动手之前；
   - 只有选了颜色，**删除 / 更换颜色**才会亮；**合并**要选两种以上才亮——按钮灰着就说明还没选够（块模式下同理：选中至少一块才会亮）；
   - 没有「恢复自动匹配」这个按钮了：**撤销本来就能把手工换的颜色退回去**（换颜色也是一步编辑，和删除、合并一样进历史），多一个换名字的回退按钮只是多一个要记的东西。撤销回去以后，那一行的色差说明会自己恢复成「图片颜色与匹配颜色的差距 ΔE00 …」；
   - 所有编辑都是**在原图匹配结果上叠加**的，原图和自动匹配结果一直都在，反复撤销恢复不会越改越糊。**会动到原图的是「删除」和「合并」**（块级 1.6.19 起、按颜色 1.6.20 起）：那是你自己指着某一块（或者某几种颜色）下的手，程序就把它坐实到图上——删除把那几片像素变透明，合并把那几片并进留下来的那一块、用**那一块本来就在的颜色**（1.6.21 起）——改过之后「原图」标题旁边会出现「**原图已修改**」，一眼看得出这张图已经不是刚导入的那张。**只有「更换颜色」原图一个像素都不动**：它只决定这块地方这一次用哪一卷来印。
6. 设置「打印宽度 / 底板厚度 / 颜色层厚度 / 底板颜色」，点「生成 3MF（Bambu Studio）」或「生成 OBJ + MTL」。保存对话框默认开在**「下载」文件夹**（`%USERPROFILE%\Downloads`；那里写不进去才退回程序自己的数据目录），默认文件名是**原图片名 + 当前时间**（例如 `猪包-20261008-143012.3mf`），不会互相覆盖。
7. **「更换颜色」对话框**列出「全部颜色」——耗材本色 + 全部混色：
   - 默认按「**按跟图片目标颜色最相似**」排序，最像的排在最上面（列表里每一项都直接写着 ΔE00）；
   - 排序下拉框和第一页「颜色配方」用的是同一套选项（RGB / 明度 / 色相 / 耗材对 / 名称），外加上面这个「按相似度」；
   - 顶部还有一个搜索框，可以按 hex、耗材名称 / 品牌 / 种类过滤；搜一个耗材的品牌 / 名称，连**由它混出来的那些混色**也一起搜得到。
   - 41 卷耗材就是 66,461 个候选。这个窗口**打开是秒开的**：它一次只建 200 行，往下滚再继续加载（列表底下写着「已列出 200 个，往下滚继续加载」），相似度排序也是一次算完，不是逐条循环。
8. 生成的模型是**一整块**跟着图片轮廓走的平面底板，上面按颜色涂不同的颜色（不是切成好几块）：
   - 3MF 里颜色直接写进模型本身（`<basematerials>` + 每个三角面的 Bambu `paint_color`），Bambu Studio 打开就是匹配到的那些颜色，不会再被 AMS 里随便哪个耗材的颜色顶掉；
   - 模型是**一个真正水密的实心体**（`0` 个开放边、`0` 个非流形边）：底板下表面、按颜色分区的上表面、外侧立墙拼成一个闭合曲面，**没有内部墙、没有重合面**。Bambu Studio 打开时不会再报「发现 N 个开放边 / N 非流形边」；
   - 包里带着一份**完整的**工程配置 `Metadata/project_settings.config`，Bambu Studio 打开时会**一个弹窗都不弹**，并且用它当工程读：耗材列表就是你的配色（白 / 红 / 金 / 青 / 黑），不会再被 AMS 里随便哪个耗材的颜色顶掉。这份配置的来路与改写方式见 [NOTICE.md](NOTICE.md) 第 8 节；
   - OBJ + MTL 是给别的软件用的（Blender、ZBrush、切片软件等）；
9. **「原图」和「预览」都能放大看**：滚轮缩放（每次 ×1.25，最大 12×，光标底下那个像素不会跑）、按住左键拖动平移、双击回到整张。放大以后**点击挑颜色依然准**：程序用「拖动超过 3 px 才算平移」把两件事分开，想平移就拖、想选色就点，手抖一下不会把点击吃掉。**「点图片时」怎么算一次点击可以两种**（1.6.16 新增，工具栏「按当前色块重新匹配」右边那个下拉框）：**按颜色选择**就是「光标底下那个像素是哪一块」，**按色块边缘选择**会看光标**周围 10 像素内最近的色块**——眉毛、描边这种一两个像素宽的东西，按颜色选择要点得特别准，按色块边缘选择点歪一点也能选中它。选过之后**下次打开还是那一种**，**换一种选择方式本身也进撤销历史**（1.6.17 起）。**选了「按色块边缘选择」，右边清单就改成一行一块**（1.6.17 起）：清单上那些编辑按钮（多选 / 删除 / 合并 / 更换颜色）跟着改成对「块」下手，点图上也是选中整块；切回「按颜色选择」，清单和按钮立刻回到「一行一种颜色」。**这个模式下删除或合并会连原图一起改**（1.6.19 起；1.6.20 起按颜色选择下删除 / 合并也连原图一起改；1.6.21 起合并写进原图的是留下来的那一块本来的颜色，原图的颜色集合不变、变的只是色块大小），所以「原图」标题旁边会出现「**原图已修改**」——看到它就说明接下来每次匹配都是在改过的图上做的；想回到刚导入的那张，Ctrl+Z 退回去即可。**这个模式下面板标题也跟着改成「图片上色块的颜色」**（1.6.20 起）。**清单里一个都没选中时预览什么都不画**（1.6.21 起）：块模式下也一样，取消掉最后一块之后连描边一起收掉。
10. **「抖动」是干什么的**：用误差扩散（Floyd–Steinberg）把每个像素的量化误差摊给它的邻居，让渐变更平滑——代价是色块边界出现噪点，不再是干净的纯色。
    - **带透明区域的图也能勾**（1.6.12 起）：以前这里会把「抖动」变灰，因为透明背景在导入时就被排除，剩下的像素被挤成**一整行**交给量化器，那一行上任何「邻居」都是假的。现在改成先把图案**往透明区域里长出去**（每个透明像素取它周围图案的平均色，长 8 轮，还不够就用整张图案的平均色补满），再只在**图案外框 + 2 px** 的范围里做误差扩散——于是每个像素的邻居都是真实邻居，而**透明区域本身依旧不打印**（它不在结果色块里，模型上还是空的）。
    - 勾选框旁边原来那句「带透明区域的图片不能用抖动」的常驻说明也跟着删了：现在没有这个限制，那一行只在真的需要解释的时候出现。
11. **三种耗材的混色默认就在候选里**：候选颜色是耗材本色 + 两两混色 + **三种耗材**的混色（每三卷 2,556 个配比）——没有勾选框，不用你去开。三色混色从 1.6.0 起就在「颜色配方」页算好并缓存，这里只是把它一起拿来比。
    - 数量级是这里唯一的难点：41 卷料是 C(41,3)=10,660 组 × 2,556 = **2,724 万**条配方，逐条造成对象是不可能的。所以程序反过来做——不枚举候选，而是把你图片的那十几种颜色拿到三色混色的 Lab 表里做一次**分块最近邻**，只有真正被选中的那几条才生成可显示的条目。
    - 结果就是：41 卷料的候选池是 **400 多万条**，匹配因此比只用本色 + 两色**慢几秒**（不是卡死）。这个代价是默认付的，不需要你决定要不要花。
    - 三色配方要先在第一页「颜色配方」里算完（那是一次性的、有缓存的长计算）。**没算完之前，这一页只拿本色 + 两色匹配**，算完会自动接上——你不用等，也不用点任何东西。
    - **三色只有在比两色更接近时才会被选中**：同一个颜色如果一卷料或一对料就能混出来，程序仍然用那个更省换料的答案。为了这一点，最近邻搜索给「本色 + 两色」那一批**单独留了一次筛选机会**，再宽的候选池也不会把一个更省料、同样接近的答案挤出局。
12. **「颜色数量」默认 32，「耗材上限」默认 4**：这两个数是**这次打印的实际约束**，不是审美偏好，所以默认值取的是「一台常见 Bambu 机器能做到的」——4 卷 AMS（上限 4），而 32 是 Bambu Studio 自己的天花板。
    - **「耗材上限」**：这次打印**最多用几卷料**，`0` = 不限制。填 3 就是「我这次只装了 3 卷」，程序会把配色压到 3 卷以内：装不下的颜色，用**最接近的、只用得起的**颜色代替。
    - **方案永远不会超过上限**：上限是你对这台机器的交代，所以「多用 1 卷会更好看」这种越界的搭配**根本不会出现在界面上**——宁可把差别写成数字让你看见，也不悄悄多要一卷料。（1.6.12 之前这里会给一套「多用 1 卷」的方案，现在删了。）
    - 做法不再是「按面积贪心收料」，而是**在上限之内挑最好的一套**：先数出每个色块各需要哪几卷（混色会要两卷或三卷），再把上限内的卷组合逐个评分（色块的 ΔE00 按像素加权求和），选最好的那样一套。贪心的毛病是最大的那块先挑走一卷，小色块（比如猪鼻子那几百个像素的洋红）就没料可用了——换成挑最好的一套以后，同一个上限里的加权色差从 1.813 降到 1.249（实测，差 31%）。
    - 组合太多时（比如 22 卷里挑 4 卷）不会硬穷举：先按「每块最需要的卷」增量搭一套，再逐个位置试换，换不动就停。
    - 预算是在**合并近似色之后**才执行的：两个肉眼分不出的色阶被折成一个，本来就能白捡一卷料回来。
    - 预算小到连一种颜色都放不下时（比如只给 1 卷、而图片只能靠两色混色），程序不会拒绝，而是换成**单卷料**里最接近的那一色——宁可颜色差一点，也不给你一个用不了的方案。
13. **「耗材方案」面板：同一个上限里有好几种搭配，你自己挑**（1.6.12 新增）。匹配完，右侧最上面那个面板会列出**几套各不相同的搭配**，每套都**在耗材上限之内**：
    - 每行是一套料，写着它挑这套的理由（**总体最接近** / **最不像的色块优先** / **小色块优先**）和它的代价：**平均 ΔE00 · 最差 · 差块 · 用几卷**。「差块」= **图片里有几种颜色**打出来偏差超过 ΔE00 5（**按图片自己的颜色数算**，1.6.15 起）——猪鼻子那种小面积的颜色混不出来时，第一套的「平均」可能很好看，「差块」却比另一套多。4 卷料去印一张有 30 种颜色的图，这个数天生就是 12～18：**只在同一套口径的行之间比才有意义**（1.6.14 的「平均」好看，是因为它按**折出来的块均值**算分，把眉毛、眼睛这种几百像素的深色折进周围大片浅色里摊平了，细节丢了分数照样漂亮）。
    - 行末几个**小颜色方块**就是这一套要装的那几卷料，按用量排（**1.6.14 新增**）：鼠标停上去写着是哪一卷、占多少。所以一行不用起名字就知道它跟下面「共 N 卷」那几行说的是同一批卷，也不再给搭法起「（备选 1）」这种称呼。
    - 那些**解释文字不在面板上了**（1.6.14 起）：三种口径各是什么意思、「差块」怎么定义，都挪到右上角「帮助」窗口里；面板上只留当时的状态。
    - **还没导入图片时，面板开头那两句一起出现**（1.6.18 起）：「匹配一张图片后，这里会列出几套耗材搭配，自己挑一套。」和它下面紧接着的「匹配完成后，这里列出这一版用到了哪几卷耗材，以及各卷占的色料比例。」——上一句说方案表会有什么，下一句说它下面的用量行会说什么，是配成一对的两句话，所以**刚打开软件就都写在那里**。1.6.17 里第二句要等第一次匹配或编辑走完才补上，那时用户只看得到上半句；而且面板多余的高度会平均分给两个标签，各自被摊到一百多像素高的槽里、文字在槽里垂直居中，看上去像分散在两个不同的盒子（1.6.18 把多余高度交给面板末尾的空白，两句话就贴着筛选行往下排）。

      ![刚打开软件：两句话都在面板开头](samples/picture-fresh.png)
    - **「耗材方案」面板能一路往上拖小**（1.6.14 新增）：它和下面「打印图片需要的颜色」之间的分隔条可以自由拖，拖到只剩标题也行（还能整个收起来），腾出来的高度全给颜色清单；以前面板的最小高度被「用到的耗材」那一段撑住，拖到一半就被顶回来。
    - 数字不是替你下结论，是让你用**自己的眼睛**选：比如同一张猪脸（41 卷档案、上限 4 卷），**总体最接近**（平均 2.20、最差 15.49、差块 18）整张最像；**小色块优先**（平均 2.45、最差 28.00、差块 12）差块最少，小面积的颜色最跟得上；**最不像的色块优先**（平均 4.40、最差 15.49）先把差得最明显的那块拉回来，平均会稍差。三个数字都是**图片自己的每种颜色**按像素加权算出来的（1.6.15 起），行上的数、排行的数、换方案用的数是同一个量。
    - 一套一样的搭配不会重复列（列出的套数按图片和上限自己变）。点一行就换成那一套，整页（预览、色块、用到的耗材、导出）都跟着换；换之前如果已经手工改过颜色，会先问一句要不要放弃那些改动。**换一套之后预览里那个高亮/描边会被清掉**（1.6.15 起）：没点颜色就什么都不画，点了哪个颜色才压暗其余部分并描边。**列表和预览永远说同一件事**（1.6.16 起）：删除、合并、更换颜色、撤销之后，预览高亮的就是列表里选中的那一块——不会再出现「列表里一行都没选中，预览却还压暗着上一块」。
    - **同一套理由下还会多给几种搭法**（1.6.13 新增，1.6.14 起不再带序号；1.6.15 起每套口径给到 5 / 4 / 4 行）：后面几行是同一个理由下**别的卷组合**（卷集合都不一样，重复的不列），不是换了一套评分口径。它们的名字跟第一套一样，靠行末那几卷的颜色区分——**名字只说明按什么标准挑的，选的是卷**（1.6.14 之前写作「总体最接近（备选 1）」，序号说不了自己跟第一套差在哪）。同一套口径里，**第一行就是这套标准能拿到的最优解**（1.6.15 起：先合并所有口径找到的候选，再用同一套数字重排）。
    - **「筛选耗材」：先说好哪几卷必须用、哪几卷不要用**（1.6.13 新增）。点开是一行一卷，**点一下换一个状态**：不要求 → 必须有 → 不要用（行上同时用文字前缀、粗体和删除线表达，不只靠颜色）；「全部不要求」一键清空。设好之后**「重新匹配」和「按当前色块重新匹配」都照它来**：「必须有」的卷每一套搭配都会用上，「不要用」的卷哪一套都不碰。如果「必须有」的卷数已经超过「耗材上限」，对话框会当场说明「不会有搭配能满足」——省得你等一次注定失败的匹配；真筛到一套都不剩时，状态栏会写「按现在的筛选条件没有找到能用的耗材搭配，先放宽筛选或者提高耗材上限。」
    - **「用到的耗材」清单就在这个面板里**（1.6.13 起）：上面那一行选出「用 4 卷」，下面紧接着就是这 4 卷各占多少——挑哪一套就显示哪一套（详见下面第 15 条）。
    - **「按当前色块重新匹配」**（1.6.13 新增，在工具栏「重新匹配」旁边）：拿**现在这些色块**重新挑卷，而不是回头再读一遍原图。所以你自己**删掉的色块不会回来**、**合并过的色块在原图里就是一整块**（它用的是那一块本来的颜色，1.6.21 起，所以「用原图剩下的色块颜色去匹配」这句话是字面成立的）、**手工换过的颜色也留着**——适合「我就要这个颜色组合，帮我重新配一次料」。它同样受「耗材上限」和「筛选耗材」约束，跑完照样列出几套方案让你挑。想回到原图给出自动答案，点「重新匹配」。
      - **方案表的一行是「一套卷组」，所以颜色少了行就少了**（这一点 1.6.20 起写进「帮助」）：能凑出多少套卷组，取决于图里有几种颜色。你按它之前刚删掉几种颜色时，图里能用来搭配的颜色变少，卷组的余地就变小，于是列出来的行会比「重新匹配」之后少——这不是少给了你方案，而是这张图真的只剩那么几种搭法。想多看几套，先把「颜色数量」调大、重新匹配，让图里有更多颜色。
     - **它会尽量保住每一块**（1.6.16 修）：以前它会把「一卷料装不下」的色块折进最接近的能印的颜色里，于是你合并好的 6 块可能只剩 2 块、细节全没了（点一下就把改好的图毁掉）。现在每一块都可以换一个**跟别的块共用同一批卷**的配方——块还在、配方可能换，代价是那一块的色差数字会变；它不再靠「把这块并到那块去」来省料。同时它**能撤销了**（见上面第 5 条的 Ctrl+Z），点错了退回来就是。
     - **它不再卡住窗口**（1.6.18 修）：41 卷料时这个按钮要停几秒、界面一动不动，状态栏一直写着「正在匹配：在耗材与混色库里寻找最接近的颜色…」。原因有两个，都修了——一是它把**四百万个三色混色**也逐个建成条目、按「这一色花哪几卷」分组，而这里要问的卷组只用得到一卷或两卷（三色颜色永远答不上），所以现在只扫前面那批单卷/两卷混色（实测 5 卷档案上这一步从 3.20 秒降到 0.04 秒，整次重新匹配 3.62 秒 → 0.47 秒）；二是这一段**一句进度都不报**，进度条就停在搜索那一步不动。现在扫描、逐块找可替换颜色、试搭配全程都报进度（见第 14 条）。
    - 选中的那一套会跟着工程一起存下来（见下面第 16 条）：下次打开工程，面板里写的就是你当时挑的那一套，**不会偷偷给你重算一套**；想再挑一次就点「重新匹配」。**打开工程时，别的搭法也会一起列出来**（1.6.20 起）：文件里只记得住挑中的那一套，别的卷组本来要先按「按当前色块重新匹配」才看得到；现在打开工程就顺手算好摆在下面，**当前这一套仍然是文件里那一套**（勾还在它上面）。算不出来（没有耗材、筛选条件太紧）时面板保持原样，不耽误你打开工程。
14. **匹配有进度，看得见它在干什么**：导入图片和「重新匹配」都要在一张几十万到几百万色的候选表里逐块找最近色——小档案（5 卷）半秒多就完了，**41 卷档案首次匹配要 7.8 秒**，其中逐块找最近色占 6 秒左右。所以状态栏会写明**正在做哪一步**（读图 / 缩小到「最大边长」 / 数颜色 / 寻找最接近的颜色 / 分配颜色 / 合并近似色 / 统计），**旁边那条进度条**跟着走（1.6.18 起它在状态文字右边，一眼能同时看到「在做什么」和「走到哪儿了」；以前它是状态文字上面一条 10 像素高的通栏细条，很不起眼）。
    - 进度条**不是一按就弹出来**：先等 200 毫秒。五卷料的小图半秒就匹配完了，让一条进度条闪一下比没有还烦；超过 200 毫秒才说明这一步值得等，那时才显示。
    - **每一步都报，不会中途停住**（1.6.18 修）：候选表大起来以后，扫描（欧氏距离逐个色块过表）和逐块挑最近色（CIEDE2000）各要好几秒，以前只有这两段结束时才报一次；现在每扫过一个色块块、每挑完一批颜色都报，「按当前色块重新匹配」的每一段（读当前色块 / 扫描 / 精确比色 / 换「必须包含」 / 换掉「不要用」 / 给每个色块找可替换的颜色 / 试着搭配耗材）也都报。进度只增不减，最后一条一定是 100%。
    - 匹配期间界面不会假死：画面照常重绘、进度照常刷新。这段时间里点不动「重新匹配」——不然会同时开第二次匹配。
15. **「用到的耗材」清单：这一版要拆哪几卷**。匹配完成后，它就列在「耗材方案」面板里选中那一套的下面（1.6.13 起从右下角搬到这里，跟「选了哪几卷」摆在同一张卡里），列出**这一版用到的每一卷料**和它占的色料比例。
    - 它回答的不是「这个模型需要哪些颜色」：一块「白 90% + 金 10%」的区域，耗的是 **90% 的白 + 10% 的金**；按颜色块数或像素数去数会得到另一个答案（那一块在白和金头上各算 1）。这一栏数的是**耗材**，所以一个混色会摊到两卷或三卷上，和左边的颜色清单本来就对不上行。
    - 每行带那卷料自己的色块和名称，比例是**质量占比**（同一颜色里按配方百分比摊到各卷，再按像素占比求和，所以所有行加起来是 100%）。删除 / 合并 / 更换颜色、撤销恢复，都会立刻重算。**整条清单排成一排**（1.6.15 起）：`共 4 卷： 肤色 93.9% · 红色 3.0% · 黑色 1.9% · 橙色 1.2%`——色块、卷名、占比绑在一起，宽度不够时在卷与卷之间换行，不会把一卷料拆成两行。
    - 打开一个工程时，如果里面某卷料**这台机器的耗材库里没有**，这一行仍然会列出来并注明「耗材库里已经没有这一卷」，颜色用文档里存着的那一个：它不会假装还在，也不会编一个颜色出来。
16. **改到一半能存成工程，下次接着改**：**Ctrl+S 保存**、**Ctrl+Shift+S 换个名字另存**，工具栏上也有「保存工程」「打开工程」两个按钮。
    - 一个工程就是**一个 `.bpproj` 文件**（其实是个 zip，里面装着 `工程.json` + `原图.png` + `预览.png` + `基线.npy`）。图在文件里面，所以复制给别人就只有一个文件，不会出现「发了个工程但打不开，因为图没了」。
    - 里面记着：原图、这张预览、自动匹配的基线、你做的删除 / 合并 / 更换颜色、**在「按色块边缘选择」下对具体色块做的改动**（哪些像素属于哪一块、改成了什么颜色，1.6.17 起）、**原图是不是已经被块级删除 / 合并改过**（1.6.19 起：存进去的就是改过之后的图，重开工程时「原图已修改」照样亮着）、用到的配方（两色和三色）、打印参数（宽度 / 底板厚度 / 颜色层厚度 / 底板颜色）、**这一版选的「耗材方案」**（`总体最接近` / `小色块优先` 这样的名字）以及**这一版用到的耗材**（名称、品牌、种类、颜色）。
    - 「打开工程」会把这一页恢复成保存时的样子：连「颜色数量 / 耗材上限 / 最大边长 / 抖动」也照着文件里记的恢复，这样再点「重新匹配」得到的是你存下来的那张图，而不是拿当前窗口的设置偷偷重算一遍。工程里存的那一套方案**照原样列出来**（面板里写「工程里存的那一套」），不会拿现在的耗材库偷偷重算一套给你；**同一批色块的其它搭法会补在它下面**（1.6.20 起），当前这一套仍然是文件里那一套。
    - **有没保存的改动时，打开别的工程或导入新图会先问一句**（先保存 / 不保存 / 取消）。保存对话框默认开在**「下载」文件夹**，和导出的模型一样——工程文件是要拿去接着改、可能还要发给别人的东西，存在程序自己的数据目录里等于让人找不到。
    - 工程文件**不包含耗材库本身**：它在哪台机器上打开，就用那台机器的耗材库接着算。所以别人拿到你的工程，得自己先建好（或导入）那几卷料；文件里记着用到的卷的名字和颜色，照着建就行。
17. **右上角「帮助」：这一页的说明收进一个窗口**（1.6.14 新增）。这个按钮以前叫「关于」，只讲版本与算法出处；现在它装着整本说明，点开是一个**可滚动、文字可选中复制**的窗口，而且**不是模态的**——开着它照样操作，照着一行行做。
    - 「图像转换这一步」那一节：原来压在图片上方的那四行常驻说明（滚轮缩放 / 按住左键拖动平移 / 双击还原整张、32 是 Bambu Studio 自己的限制并已提工单、改到一半能存成工程接着改、双击清单里的一行看详情、「筛选耗材」、「按当前色块重新匹配」）全都在这里；**还有「点图片时」那两种方式各自什么时候更好用、为什么「按色块边缘选择」下清单会变成一行一块**（1.6.16 / 1.6.17 起）、**「删除」也能按 Del，以及删除 / 合并为什么连原图一起改、改完哪里会标「原图已修改」**（1.6.19 起；1.6.20 起按颜色的删除 / 合并也一样、按钮上不再写「(Del)」、面板标题随模式换字、「单选时再点一下就是取消选中」、打开工程会补齐别的搭法、以及「为什么「按当前色块重新匹配」之后方案变少」（1.6.21 起还加上「清单里一个都没选中，预览就不画」和「合并之后原图的颜色不会变多——写进去的是留下来的那一块本来就在的颜色」）；
    - 「耗材方案」那一节：三种口径各自在挑什么、「差块」怎么算的；
    - 最后一段是版本号与算法出处，和 exe 文件属性里的号是同一个来源；
    - **页面上不再常驻任何解释文字**：这些话只在你要读的时候出现，不挡着正在看的图。

## 二、混色是怎么算的

程序内置**三个**混色预测引擎，可以在第一页左上角切换：

| 引擎 | 说明 |
| --- | --- |
| **Bambu 混色预览**（默认） | 完全按 Bambu Studio **2.8**（02.08.x）的对话框算法复刻：调用 Bambu 内置的 `filament_mixer` 颜料混色多项式（近似 Mixbox 的四次回归）。**你在现在这版 Bambu Studio「效果预览」里看到的颜色就是这个**，所以拿它来配对最准。 |
| **Bambu 2.5 旧版预览（sRGB 平均）** | 2.5.x 及更早版本的算法：对两个 8 位 sRGB 通道做加权平均。如果你的 Studio 还停在旧版，选这一项才对得上。 |
| **光谱 KM 模型** | 把 sRGB 反推成 31 段可见光反射率（ICC 多项式估计），转成 Kubelka-Munk 的 K/S，混合后再转回 Lab/sRGB。物理上更接近真实颜料混合，颜色比另外两个更暗、更「实」，但与 Studio 的预览值对不上。 |

怎么知道默认引擎是对的？用你给的两张截图验证过：纯白 + 纯黑在 90/10 和 10/90 时，
**颜料多项式算出的预览色与截图里的色块逐字节相同**（`#CBE4EE` / `#041D2E`），
而旧版 sRGB 平均在这两处分别差 27 和 21 个色阶。细节见 [`docs/算法说明.md`](docs/算法说明.md) §1.3。

**你的选择会被记住**（打包版存在 exe 旁边的 `data\settings.json`，从源码运行存在
`%LOCALAPPDATA%\BambuPalette\settings.json`），
下次打开还是你选的那个，不用每次重设。旧版本存过的选择会自动升级到新默认值，
除非你在新版里明确选了别的。

详细的算法出处、公式和溯源见 [`docs/算法说明.md`](docs/算法说明.md)，第三方代码与数据的授权见 [`NOTICE.md`](NOTICE.md)。

## 三、直接运行 exe

```
dist\BambuPalette\BambuPalette.exe
```

双击即可，不需要装 Python。想确认这台机器上跑得起来，可以在命令行里执行一次自检：

```powershell
.\dist\BambuPalette\BambuPalette.exe --selftest
```

它会在当前目录写出 `selftest-report.txt` 和一张界面截图 `selftest-ui.png`，逐项检查
混色引擎（默认引擎是哪一个、颜料多项式的上游样例能不能复现、旧版 sRGB 引擎是否仍然精确）、
图片匹配、建模和 3MF/OBJ 导出是否正常，最后打印 `SELFTEST OK`。**每一项都通过才算正常**
（1.6.21 的发布包实测 333 项）。

**数据存在哪里**

- **打包版（exe）：就在这一份程序自己旁边**——`data\filament-library.json`。**每一份解压出来的程序
  都有自己的一份**，互不相干：解压一个新版本，它从**空耗材库**开始（「我的耗材」是空的，得点「导入」
  才看得到耗材），不会莫名其妙继承上一份的耗材。想让新的一份接着旧的那份用，先在旧的里点「导出」，
  再到新的里点「导入」——「导入」默认就开在旧档案所在的文件夹（见下一条），不用自己去猜路径。
  这样做还有一个好处：两份副本各自是什么样永远说得清，自检和截图也不会被「上一份留下的耗材」污染。
- 从源码运行：`%LOCALAPPDATA%\BambuPalette\filament-library.json`（不往代码目录里写东西）。
- 便携模式：在 exe 同目录放一个空的 `portable.txt`，数据固定存在 exe 旁边的 `data\` 文件夹里（放 U 盘里带走很方便）。1.6.11 起打包版默认就是这个行为，所以 `portable.txt` 现在主要用于从源码运行时把数据钉在代码目录旁边。
- 旧版留下的那一份（`%LOCALAPPDATA%\BambuPalette\filament-library.json`，更早的叫
  `%LOCALAPPDATA%\FilamentColorStudio\filament-library.json`）**新版不会再自动读**。它是你的耗材，
  所以当这一份还没有档案时，点「我的耗材」下面的「导入」，对话框会**直接开在**它所在的文件夹。
- 导出的 3MF / OBJ 默认保存到**「下载」文件夹**（`%USERPROFILE%\Downloads`）。这里**不做写入探测**：探测回答的是「本进程能不能在这里建文件」，而你要的是「我想在哪儿找到它」，两个问题不一样——1.6.5 就是因为先探测，打包成 exe 后探测失败，导出的文件全落回了隐藏的私有目录。真写不进去时会在写入处兜底，改存到程序自己数据目录下的 `exports\` 或用户主目录，并弹窗告诉你文件到底在哪。
- **程序一定放得下数据，也一定打得开。** 首选目录用不了时会依次退到带副本名的
  `%LOCALAPPDATA%\BambuPalette-<副本名>\`、`%TEMP%\BambuPalette-<副本名>\`、用户主目录下的
  `.bambupalette-<副本名>\`，每一步都会把已有档案带过去；只有全部失败才弹出说明窗口。
  副本名是 exe 所在文件夹名（去掉程序自己的名字）加 6 位摘要，比如
  `BambuPalette-1.6.11-win64-e773f6`——**退路也是按副本分开的**，两份同名的副本不会共用一份档案。
  触发条件通常是杀毒软件临时锁目录、漫游配置重定向，或者 Windows 把刚删掉的目录留在 "delete pending" 状态。

> **怎么判断"用不了"**：不是看目录在不在，而是**真的建一个探测文件再删掉**。Windows 允许进程"看见"一个它无权
> 写入的目录，而且对已存在的目录调用 `mkdir` 即使没有写权限也会成功——只看存在性会把一个拒绝写入的目录当成
> 好目录。这一点曾经造成真实的 bug：保存档案时用的 `tempfile.mkstemp` 在 Windows 上会把"持续拒绝写入"误判成
> "文件名撞车"，然后按 `TMP_MAX`（2147483647）一直重试，于是**双击打不开程序**——窗口还没显示就卡在
> `MainWindow.__init__` 里的那次保存上，单核跑满。现在保存改成有上限的 `open(..., "x")` 重试，拒绝写入
> 会立刻变成一句可读的错误，不会再空转。
>
> 同理：**已经有档案的目录优先于顺序**。如果程序曾在降到低完整性级别（或目录被锁）时把档案写到了 exe 旁边，
> 之后首选目录恢复可写也不会把那份档案丢下——否则用户会看到耗材"凭空消失"。

> 早期版本叫 **FilamentColorStudio**（界面标题「混色耗材管理器」）。如果你机器上已经存在旧目录
> `%LOCALAPPDATA%\FilamentColorStudio\`，只在这份程序**自己旁边写不进去**、真的退到
> `%LOCALAPPDATA%` 里的时候才会自动把它改名接管过来（改名被系统拒绝、或者目标目录已经存在但是空的
> ——上一次启动中断会留下这种目录——就改成把旧文件复制过来，已经存在的文件一律不覆盖）。
> 正常情况下 1.6.11 的副本数据在 exe 旁边，那份旧档案不会被动，需要时用「导入」读进来。

用法：打开程序 → 点「我的耗材」卡片下面的 **「导入」** → 选这个 JSON。导入是**追加**，不会清掉你已有的耗材。

导入 41 种之后：`C(41,2) × 81 = 66,420` 个混色，第一次算完大约 **0.8 秒**
（1.2.11 把混色多项式换成「按父项相乘」，快了 4 倍，见 §20）。
之后再**加一卷 / 删一卷只要零点几秒** —— 程序只补差额，不会整表重算，
已经算好的混色对象原封不动保留（见 `docs/算法说明.md` §15）。
启动时也**先出窗口再算表**：窗口立刻出现，状态栏写着
「正在计算 66,420 个混色，请稍候…」，不会看起来像卡死（见 §16）。

![启动时先出窗口](samples/startup-calculating.png)

「图片转模型」页载入图片后，改动耗材库不会再把时间花在你**看不见**的
那张结果上 —— 在「颜色配方」页改一次耗材只要 0.22 秒（原来 1.34 秒），
切回「图片转模型」页时它才补做匹配（见 §17）。

「更换颜色」和「重新匹配」共用的那张候选表只建一次（41 卷 66,461 个候选，
建表本身要 0.33 秒），打开对话框从 0.48 秒降到 0.19 秒（见 §18）。
导出模型那两秒也不是闷着的：鼠标变成等待圈、状态栏写着「正在生成模型…」
「正在写入 xxx.3mf…」（见 §19）。

建表本身也快了：混色多项式的 330 个单项式改成「按父项相乘」，
不再对每个元素单独调 `pow()`，特征矩阵从 2.68 秒降到 0.28 秒，
整表 3.14 秒降到 0.82 秒，且**输出与旧版逐位相同**（见 §20）。

**混出同一个颜色的配方会合成一张卡片。** 上面 41 卷的 66,420 个混色里，
有 6,772 个和别的混色算出了完全相同的 `#RRGGBB`，合并后网格里是
**59,648 个颜色**。点开其中任意一个，右边除了照旧显示它的第一条配方，
下面还会列出**合成这个颜色的所有配方** —— 极端例子是 `#8F8F8F`，
有 18 种不同的配比能混出它。侧栏高度不够时自己滚动，不会把行压扁（见 §22）。

![合成一个颜色的所有配方](samples/merged-colour.png)

**三色混色（默认关闭，勾选「全部混色」标题栏上的「三色混色」）。** 三卷耗材按
**1 % 步进**混合，`a + b + c = 100` 且每种至少 10 %，一共
**2556** 个配比（`C(72,2)`，见 §23.1），用的是 Bambu Studio 自己的
「从左往右依次合成」算法。所有三卷组合都算，算完同样按颜色合并：
41 卷是 10,660 个组合、**27,246,960 条配方**，去重后 **4,295,101 个颜色**。

这个规模不可能一次算完，所以它**边算边显示进度**（状态栏写着
「正在计算三色混色：x / 27,246,960（n%）」，界面不卡），
算完把结果缓存到数据目录，**下次打开同一套耗材直接读缓存**（见 §23.5、§23.6）。
几百万个格子用惰性序列 + 算术布局来画，滚动和点击都是 O(1)（见 §23.4）。

三色混色打开期间，搜索框和「全部颜色」会暂时禁用 —— 430 万个颜色没法逐个套名字，
耗材本色也没法插进一个保持排序的 430 万长序列里（见 §23.7）。

**导出会把混色表一起带走。** 三色表已经算好时，「导出」除了写耗材档案 `.json`，
还会在旁边多写一个同名的 `.mixes.npz`（41 卷约 153 MB；没算过就只写 JSON）。
下次「导入」这份档案，程序先核对缓存是不是确实属于这套耗材，
对得上就直接用，**不用再等那 249 秒**（见 §23.7）。

本机缓存只留最近 3 份（`数据目录/cache/triples-*.npz`）：加一卷耗材就会换一个
指纹，不清的话每编辑一次就多占 153 MB。另外只要耗材库或混色模型变了，
正在算 / 已经算好的三色表都会作废重来，绝不会拿旧配方冒充新耗材库
（见 §24）。

## 六、已知限制

- **3MF 已经在真实的 Bambu Studio 里验证过了**（见下节），验证的是「能被正确读入、几何与挤出机号完整保留、**按顶点索引数**没有开放边/非流形边、顶点逐面颜色与往返前完全一致」；实际切片打印效果还需要你自己试一次。
- 打开导出的 3MF 时，Bambu Studio **不再弹任何对话框**（1.6.6 及以前会弹「3mf文件配置无效，仅加载几何数据」，原因与修法见 [docs/算法说明.md](docs/算法说明.md) 第 33 节）。
- 工程配置里带的机器 / 工艺预设是**模板里那份**（`Bambu Lab A1` + `0.20mm Standard @BBL A1`），所以打开后 Bambu Studio 左上角的打印机会变成 **Bambu Lab A1**。**切片前记得切回你自己的机器**——这一点和从 Makerworld 下载的别人的工程文件是一样的。耗材列表里的 5 个颜色始终是你导出时的那 5 个。
- 混色只在**同一种耗材种类**之间成立（Bambu Studio 本身也是如此，种类不同不允许混色）。程序不会阻止你给不同种类的耗材算混色，但去 Bambu Studio 里会发现混不了。
- 图片匹配是逐像素取最接近的颜色，「颜色数量」上限 **32**；照片类图片建议 8–16 色，否则打印出来会非常碎。
- **为什么是 32**：这是 Bambu Studio 自己的限制，不是本程序的选择。一个工程里只认 **32 个耗材位**（`EnforcerBlockerType::ExtruderMax`），第 33 种颜色在切片时会被**静默丢掉**——那几块会被当成没涂色，跟着对象/全局耗材打。混色之外还想再加颜色的话，只能靠「耗材上限」把方案压到 32 以内。我们已经就这条限制向拓竹提了工单；等它放开，这里才能跟着放开。相关源码位置见 [docs/算法说明.md](docs/算法说明.md) 第 35 节。
- 三色混色只在**自动匹配**里可用，手动「更换颜色」的列表仍然只列本色和两色混色：那个列表是给人翻的，400 万行翻不了。
- 被**隐藏**的耗材不参与任何东西（混色、全部颜色、图片匹配、导出），但它那一行还在表里；隐藏状态只写进档案里需要它的那一条。
- 底板是按像素矩形拼出来的，分辨率很高时三角形会比较多（示例图 150 mm 宽约 2 千个三角形），切片正常，但如果要更精细可以适当调低「最大边长」。
- 如果你解压到的文件夹**带着 Low 完整性标签**，程序会被 Windows 降级到低完整性级别，于是**存不进「下载」/「桌面」**（报 `Permission denied`，或者系统弹「你没有权限在此位置中保存文件」）。这**不是程序的问题，也不是权限设置坏了**：是那个文件夹自己的标签。想确认就跑一句 `icacls "<文件夹>"`，看到 `Mandatory Label\Low Mandatory Level` 就中招了；修法是 `icacls "<文件夹>" /setintegritylevel Medium /T /C /Q`。**从 zip 正常解压出来的副本不会有这个标签**（zip 里不存完整性标签），所以绝大多数人碰不到。完整来龙去脉见 [docs/算法说明.md](docs/算法说明.md) 第 34 节。

## 七、3MF 的正确性是怎么验证的

这台机器上装的是 **Bambu Studio 02.08.02.61**，所以 3MF 不是「照着格式猜的」，而是拿真的 Bambu Studio 跑过一遍往返：

```powershell
.\.venv\Scripts\python.exe tools\verify_bambu_roundtrip.py
.\.venv\Scripts\python.exe tools\verify_bambu_roundtrip.py samples\sample-plate.3mf
```

不带参数时脚本会自己造一块小板；带上 `.3mf` 路径就验证那个现成文件。

它把生成的 3MF 交给 `bambu-studio.exe --export-3mf <输出> <输入>`——Bambu Studio 会读入模型、建场景，再导出一份新的工程文件。然后逐项比对源文件与回读文件的顶点数、三角面数、部件数、逐面色编码，以及**这一块网格到底水密不水密**（**按顶点索引**数开放边和非流形边，也就是 Bambu Studio 对象面板上「信息 / 错误」那两行）。

> 这里**故意不做顶点焊接**。1.6.5 及以前是先按坐标焊接再数，那一步把「同一条边被存成两个不同索引对」这个缺陷整个盖住了：焊接后是 0，Bambu Studio 数出来是 14,650。数的人怎么数，比数多少次重要。

实测结果（示例文件 [samples/sample-plate.3mf](samples/sample-plate.3mf)）：

```
source      :   31,363 B  1,008 vertices  2,012 triangles  1 parts  5 paint codes
              part 1: extruder None  混色底板示例
              filaments: #F2F0EB #C8342E #D9A441 #2FA8B8 #17181C
              paints: 0C×266  1C×472  2C×27  4×1,188  8×59
              mesh: 0 open edges  0 non-manifold edges
round trip  :   51,711 B  1,008 vertices  2,012 triangles  1 parts  1 meshes
              part 1: extruder None  混色底板示例
              filaments: #F2F0EB #C8342E #D9A441 #2FA8B8 #17181C
              paints: 0C×266  1C×472  2C×27  4×1,188  8×59

BAMBU ROUND TRIP OK
```

源文件的 `filaments:` 读的是模型里的 `<basematerials>`（`BambuPalette` 的读入路径只认那里），工程配置里的耗材表在 `Metadata/project_settings.config`，两者写的是同一组颜色（见 §二第 8 条和 [docs/算法说明.md](docs/算法说明.md) 第 33 节）。颜色靠 `<basematerials>` + `paint_color`，五个编码和逐项计数在往返前后完全一致。开放边 / 非流形边这两项一旦不是 0，脚本会直接判 FAIL——它们是用户在 Bambu Studio 里一眼就能看见的两行红字。

> 这一步曾经抓出一个真实缺陷：最早的 3MF 是照抄 Bambu Studio 自己导出工程的布局（每个部件一个 `3D/Objects/object_N.model`，用 3MF production 扩展的 `<component p:path=…>` 跨文件引用）。Bambu Studio 2.8 会**保留元数据却把全部 component 丢掉**，回读出来 `face_count="0"`、几何全空。改成标准 core 3MF（网格全部内联在 `3D/3dmodel.model` 里，component 只按 `objectid` 引用）之后往返完全一致。现在 `tests/test_export.py` 里有专门的回归测试守着这条：不许出现 `3D/Objects/` 条目，且每个 `<component>` 必须能解析到真正带网格的对象。

## 八、未来更新方向

按"用户最可能想要"的顺序排列，不是承诺的时间表。每一条都写清楚**现在卡在哪**，方便你判断要不要提。

### 想做、且已经知道怎么做的

1. **把"自己打印出来的真实颜色"录回去校正引擎**
   现在三个模型都是"猜"：颜料多项式是上游回归出来的、sRGB 平均是 Bambu 2.5 的算法、KM 是物理近似。
   但真实打印还受层高、底材、温度、耗材批次影响。计划加一栏"实测颜色"：你打完一块色卡，
   把实际看到的颜色填进对应的颜色配方里，程序用这些点对当前引擎做一次局部校正，
   并明确标出"这个配方是实测过的"。这会把工具从"预测"变成"越用越准"。

2. **多份耗材档案在界面里切换**
   1.6.11 已经把"每一份副本自己一份档案"做实了（数据就在 exe 旁边，互不相干），
   但换档案还得靠「导出 / 导入」。想做的是同一个程序里存好几套（例如"工作室 / 家里"），
   在界面上切换，而不是复制整个程序目录。

3. **深色主题**
   界面的调色板已经是集中定义的（`app/ui/theme.py`），补齐深色版并不难，只是需要逐个控件过一遍对比度。

### 想做、但还没想清楚怎么做的

4. **图片转模型：轮廓矢量化**
   现在是把像素矩形直接拼成台阶，分辨率高时三角形会偏多。更理想的是把颜色区域抽成轮廓多边形再挤出，
   模型会干净很多。难点是"颜色区域"在照片类图片里非常碎，需要先做一次形态学合并，
   否则抽出来的多边形比现在更糟。

5. **图片转模型：浮雕 / 高度图（可选）**
   当前导出的是**平面**底板（这是明确的产品决定）。如果加浮雕，会作为一个独立选项，
   不影响平面导出。需要同时解决"高度图如何映射到层数"和"Bambu Studio 里怎么表达"两个问题。

6. **直接和 Bambu Studio 联动**
   现在只能在界面上告诉你去 Studio 里怎么填。理论上可以生成一段可以直接导入的 Studio 配置
   （预设 / 耗材映射），但 Studio 的配置格式随版本变化且没有稳定文档，需要先确认长期可行性。

> 原来这里的第 7 条「图片转模型：把三色混色也算进候选」已经在 **1.6.9** 做完了（见第一页第 11 条），
> 所以从这张表里撤掉。当时卡住的是"手动挑选列表没法变成 400 万行"，最后的选择是：
> **三色只进自动匹配，手动列表保持两色**——这个不对称就是当初要权衡的那件事，现在按"自动匹配优先"定了。

### 明确不打算做的

- **不做网页版。** 程序是独立桌面应用，不联网、数据全在本机。
- **不做云同步、不做账号。**
- **不自动切片。** 切片交给 Bambu Studio，本程序只负责"配色"和"生成可切的模型"。
